# Welcome to Sia AI Documentation

Sia AI is a powerful business intelligence (BI) platform that allows you to interact with your data using natural language. This documentation will guide you through its core components and teach you how to leverage its features for effective data analysis.

## Core Components Overview

Sia AI is composed of several key components that work together to turn your natural language questions into data visualizations and insights.

| Component | Role | Description |
|---|---|---|
| **Chat Interface** | **Primary User Interaction** | The main page where you ask questions in plain English. The AI interprets your prompt, generates a SQL query, executes it, and returns a chart or data table. |
| **Modeling Page** | **Semantic Layer Definition** | This is where you define the "business logic" of your data. You can define models (tables), relationships between them, custom metrics, and calculated fields. This provides the AI with the necessary context about your data schema. |
| **Knowledge Base** | **Context Enrichment** | A repository for business-specific terms, definitions, and synonyms. This helps the AI understand your organization's unique vocabulary, like "What is our ARR?" or "Show me our top-performing SKUs." |
| **SQL Change Component**| **Correction & Refinement** | A powerful feature that allows you to directly view and edit the SQL query generated by the AI. This is essential for correcting mistakes and fine-tuning complex analyses. |
| **Views & Dashboards** | **Persistence & Sharing** | Allows you to save frequently used queries as "Views" and pin insightful charts to create shareable "Dashboards" for monitoring key metrics. |

### How They Fit Together: The Workflow

1.  **Modeling:** An administrator or data analyst first uses the **Modeling Page** to define the semantic layer over the raw database tables. This is a one-time setup (with ongoing maintenance) that tells WrenAI how your data is structured (e.g., `users` table joins to `orders` table on `user_id`).
2.  **Enriching Context:** The **Knowledge Base** is populated with business terms. For example, you can define "Active User" as a user who has logged in within the last 30 days.
3.  **Asking Questions:** A user goes to the **Chat Interface** and asks a question like, "Show me the number of active users per month."
4.  **AI Interpretation:** Sia AI's LLM uses the context from the **Modeling Page** and the **Knowledge Base** to translate the user's question into a precise SQL query.
5.  **Execution & Visualization:** The SQL query is run against the database, and the results are displayed as a chart or table.
6.  **Refinement:** If the AI makes a mistake, the user can use the **SQL Change Component** to correct the query. The user can then save this corrected logic as a **View** or add a term to the **Knowledge Base** to improve future performance.
7.  **Dashboarding:** If the resulting chart is valuable, the user can pin it to a **Dashboard** for easy access later.
